> 完整说明在 `skills/git-sync/README.md`。

## 零、我该用哪个文件夹？（拿不准先跑这个）

一个项目在这台机器上可能有**好几份克隆**，每份停在不同分支上；**别的分支里的文件不是你的文件**。
双击 **`where.cmd`**（或命令行 `.\where.ps1`），一次看清：

```
-> E:\0zhongqi\zhongqi-arena            ← 带 -> 的这份，config 分支 = 本会话
     branch  : arena/01a09d79-zhongqi
     config  : arena/01a09d79-zhongqi   (this folder always pulls this branch)
     commit  : 2e2aaa4 feat: 中期检查表签字页单独成完整的一页...
     download: E:\0zhongqi\zhongqi-arena_out

   E:\0zhongqi\zhongqi                   ← 另一份，属于别的会话
     branch  : arena/01a0a949-zhongqi
     config  : arena/01a0a949-zhongqi
     download: E:\0zhongqi\zhongqi_out
```

- **看 `config` 那一行**：它就是那个文件夹每次 `sync` 都会拉的分支，写在
  `skills\git-sync\sync.config.json` 里（每个分支自带一份，所以不同会话的克隆会各拉各的）。
- 本会话（中期检查表 / 答辩 PPT 这一套）的分支是 **`arena/01a09d79-zhongqi`**：
  哪个文件夹的 `config` 是它，就用哪个（`where.cmd` 会给它标 `->`）。
- 想让它直接标出你要的那份：
  `.\where.ps1 -Want arena/01a09d79-zhongqi`；想只看某一份就不加参数、在哪个文件夹里跑就标哪个。
- 交付物在**那个文件夹自己的下载目录**里（默认 `..\<文件夹名>_out\`）：
  `deliverable\`、`中间版\`、`中间版2\`。`download.cmd` 跑完会把这些路径原样打印出来，
  所以“文件到底在哪”永远不用猜。

## 一、先进哪个文件夹

本会话用 **`E:\0zhongqi\zhongqi-arena`**（如果 `where.cmd` 显示它的 config 是
`arena/01a09d79-zhongqi`）—— 这是当初用 `reclone.cmd` 另拉的干净文件夹；
交付物下载到 `E:\0zhongqi\zhongqi-arena_out\`。

**不是** `E:\0zhongqi`（那是上一层，不是 git 仓库，脚本放那儿会报 “Not a git repository”）。
**也不要用** `E:\0zhongqi\zhongqi`：如果 `where.cmd` 显示它的 config 是
`arena/01a0a949-zhongqi`，那它是**另一个会话**的文件夹（它的 `sync.config.json` 就钉在那个分支上），
里面的内容和 `zhongqi_out\` 里的交付物都属于那个会话，与本次中期材料不是一套。

判断有没有进对：文件夹里能看到 `sync.ps1`、`sync.cmd`、`where.cmd`、`README.md` 和
`deliverable`、`中间版` 这些目录。

## 二、一键同步（双击就行）

| 想干什么 | 双击这个文件 | 或者命令行 |
|---|---|---|
| **我在哪个文件夹 / 该用哪份** | `where.cmd` | `.\where.ps1 -All`（列出所有克隆） |
| **拉最新**（最常用） | `sync.cmd` | `.\sync.ps1` |
| **把交付物下载到本机** | `download.cmd`（默认下载 final 集合） | `.\download.ps1 -Set final` |
| 体检（哪里不对劲先跑它） | `doctor.cmd` | `.\doctor.ps1` |
| 首次准备（换电脑才用） | `bootstrap.cmd` | `.\bootstrap.ps1` |
| **把本地改动推给你**（改完文件用这个） | `push.cmd` | `.\push.ps1 "导师改好的中期表"` |
| 打包成 zip 交出去 | —— | `.\pack.ps1 -Set final` |

`.cmd` 只是 `.ps1` 的“双击外壳”（自动加 `-ExecutionPolicy Bypass`，避免策略拦截），行为完全一样、参数照样能传，
例如 `download.cmd -Set all` 或 `download.cmd -Set preview`。

> 为什么不用双击 `.ps1`：Windows 默认把 `.ps1` 当文本文件打开（记事本），双击不会运行；`.cmd` 才是双击即跑。

## 三、第一次用（只在没拉过脚本的旧克隆上需要）

如果文件夹里**看不到** `sync.ps1 / sync.cmd`，说明本地还没拉过带脚本的提交，先做一次裸 git（只需一次）：

```powershell
cd E:\0zhongqi\zhongqi
git fetch origin
git checkout arena/01a09d79-zhongqi
git pull
```

拉完就有 `sync.cmd` 了，以后**永远只双击 `sync.cmd`**。
（`bootstrap.cmd` 会自动做：放开执行策略 → 设 git 身份 → 切到工作分支 → 首拉。）

## 四、另起一个干净文件夹（原来的被别的分支占了怎么办）

一个文件夹的 `.git` 同一时刻只能停在一个分支上。如果 `E:\0zhongqi\zhongqi` 已经被别的分支/别的会话占了，
**最省事的做法是另拉一份，旧文件夹原样不动**——两个文件夹各有独立 `.git`，互不影响。

**办法 A：双击 `reclone.cmd`**（放在仓库根目录，旧文件夹里也有；如果旧文件夹里没有，用下面的命令版）

| 双击后 | 结果 |
|---|---|
| 不问参数 | 在**上一层**创建 `zhongqi-arena\`（与 `zhongqi\` 平级，不重名） |
| `reclone.cmd -Path E:\0zhongqi\zhongqi-arena` | 指定目标文件夹 |
| 目标已存在且是克隆 | 不重拉，直接 fetch + 切分支 + 快进 |

**办法 B：三条命令（复制粘贴，路径按自己的改）**

```powershell
cd E:\0zhongqi
git clone -b arena/01a09d79-zhongqi --single-branch https://github.com/mqgg5630-cyber/zhongqi.git zhongqi-arena
cd .\zhongqi-arena
git branch --show-current      # 应打印 arena/01a09d79-zhongqi
```

拉完在新文件夹里继续用同一套脚本：双击 `sync.cmd` 拉最新、`download.cmd` 下交付物。

> 远端上有多个 `arena/*` 分支（**每个会话一个**）。克隆时一定要写清楚本会话的分支：
> `arena/01a09d79-zhongqi`。只写 `git clone <url>` 拿到的是默认分支，再 `git checkout arena/...`
> 时如果名字打错，就会切到别的会话的分支上——这正是“文件夹被别的分支占领”的常见原因。

要点：

- `--single-branch -b <分支>` 只拉这一个分支，**不会**被别的分支状态带偏；
- 旧文件夹里的改动、stash、分支都**不会被碰**（脚本只读它的 remote 地址，写操作全在新文件夹里）；
- 新文件夹的下载目录默认是 `zhongqi-arena_out\`，与旧的 `zhongqi_out\` 分开，不会互相覆盖；
- 想省磁盘共享同一个 `.git`，也可以改用 worktree：
  `git -C E:\0zhongqi\zhongqi worktree add E:\0zhongqi\zhongqi-arena arena/01a09d79-zhongqi`
  （注意：worktree 里两个文件夹不能在同一个分支上同时检出）。

## 五、日常三条

```powershell
.\sync.cmd            # 1. 拉我（Agent）推的最新提交
.\download.cmd        # 2. 把 deliverable\ 中间版\ 中间版2\ 复制到本机下载目录
.\doctor.cmd          # 3. 出问题时先跑，一次看清 环境/分支/远端/未提交/stash
```

下载目录默认是仓库**上一级**的 `zhongqi_out\`（可在 `skills\git-sync\sync.config.json` 的 `download_dir` 改成绝对路径）。
`download.cmd` 只复制工作区里的文件——所以**先 sync，再 download**，否则拿到的是旧的。

## 六、出问题对照表

| 现象 | 处理 |
|---|---|
| `sync` 打印的分支不是本会话的 | 这个文件夹属于别的会话（它的 `sync.config.json` 钉在别的分支上）：**不要在这里 download**，先跑 `where.cmd` 找 config 是本会话分支的那份，没有就用 `reclone.cmd` 另拉 |
| 双击闪一下就没了 | 说明脚本没找到：确认文件在 `E:\0zhongqi\zhongqi` 根目录，窗口里会打印 `[exit code n]` |
| `running scripts is disabled` | 直接双击 `.cmd`（已带 Bypass）；或跑一次 `bootstrap.cmd` |
| 要密码 / 认证失败 | GitHub 不收密码：用 token、`gh auth login` 或 GitHub Desktop 登录一次 |
| 下载的文件是旧的 | 先 `sync.cmd`，再 `download.cmd` |
| 本地改动“消失” | 多半进了 stash：`git stash list` → `git stash pop` |
| 提示 `Updates were rejected` | 先 `sync.cmd`，再 `.\push.ps1` |
| **文件夹被别的分支占了 / 切不回来** | `reclone.cmd` 另拉一个干净文件夹（见第四节），旧文件夹不动 |
| 忘了选哪个文件夹 / 交付物在哪 | `where.cmd`（第零节）：列出所有克隆 + 各自下载目录 |
| 想看细节 / 更多故障 | `skills/git-sync/README.md` 第四节、第五节 |

## 七、那 15 个文件分别是什么

| 文件 | 作用 |
|---|---|
| `sync.ps1` / `sync.cmd` | 拉取工作分支最新（本地有改动会自动 stash） |
| `upload.ps1` | 传：把附件按扩展名归位到 `sources\` / `code\` / `results\` 后 commit + push |
| `push.ps1` / `push.cmd` | 提交 + 推送（先 fetch/pull 再 `git add -A`、commit、push；拒绝推 `main`）；想把导师/自己改过的文件交给我，把文件放进对应目录后双击 `push.cmd` 即可 |
| `where.ps1` / `where.cmd` | **我该用哪个文件夹**：列出本份与相邻所有克隆的路径 / 分支 / config 分支 / 最新提交 / 下载目录，标出属于你要的那个分支的一份 |
| `download.ps1` / `download.cmd` | 按集合把目录镜像到本机（`final` / `docs` / `source` / `preview` / `all`）；结束时打印来源仓库 / 分支 / 提交 / 目标目录 |
| `pack.ps1` | 打包成 `_export\日期_集合.zip` |
| `doctor.ps1` / `doctor.cmd` | 体检 |
| `bootstrap.ps1` / `bootstrap.cmd` | 首次准备 |
| `reclone.ps1` / `reclone.cmd` | 另拉一个干净文件夹（不碰当前文件夹）；目标已存在则快进 |
| `skills/git-sync/sync.config.json` | 唯一的配置：分支、远端、下载集合、下载目录、附件归位规则 |

改配置只动 `sync.config.json`，脚本不用动；`.ps1`/`.cmd` 里不许有中文（`python code/check_ps1.py` 会在提交前拦下来）。
